title: The cast of characters around your handler
---

Your controller method is called the **handler**. Nest lets you put reusable code *around* every
handler instead of copying it into each one. Those pieces have names, and the names are the
whole problem — each is just a class with one method.

| Name | One-line job | The method you write |
| --- | --- | --- |
| **Middleware** | Anything framework-level, before Nest is involved | `use(req, res, next)` |
| **Guard** | May this request continue? Yes/no | `canActivate(context)` → `boolean \| Promise<boolean> \| Observable<boolean>` |
| **Interceptor** | Wrap the call — do something before *and* after | `intercept(context, next)` |
| **Pipe** | Check/convert one argument | `transform(value, metadata)` |
| **Exception filter** | Turn a thrown error into a response for the current transport | `catch(error, host)` |

They run in a fixed order around the handler:

```
middleware → guard → interceptor(before) → pipe → HANDLER → interceptor(after)
                                    ↘ (anything thrown) ↘ filter
```

The filter isn't a step everyone passes through — it's the branch taken when something throws.
A request that succeeds never touches it.

## Middleware, and the "consumer"

Middleware is the Express-style `(req, res, next)` function — it runs before Nest's own layers
and knows nothing about which handler will eventually run. You attach it by implementing
`configure` on the module, and the object you're handed is the **`MiddlewareConsumer`**. Odd
name, boring meaning: it's the little builder API for saying *which routes get this middleware*.

```ts
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer.apply(RequestIdMiddleware).forRoutes("*");   // "consume" this middleware, for every route
  }
}
```

## Guard, and what "context" means

A guard answers one question: *should this request be allowed to proceed?* Return `true` and it
continues; return `false` and Nest responds 403. It may also return a promise or an `Observable`
of that boolean, which is what lets a guard hit a database or verify a token before deciding.

```ts
@Injectable()
export class ApiKeyGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const expected = process.env.API_KEY;
    if (!expected) return false;                 // no key configured -> fail closed, not open

    const request = context.switchToHttp().getRequest();
    return request.headers["x-api-key"] === expected;
  }
}
```

That first line matters: without it, an unset `API_KEY` makes `undefined === undefined` true and
the guard waves everyone through. A comparison-based check should always confirm it has
something to compare against.

The `context` is Nest's envelope around "the thing currently being handled". It's not
HTTP-specific, because the same guard could be protecting a WebSocket message or a queue
message — so before you can touch `request`, you have to say which world you're in:
`context.switchToHttp()` (or `switchToWs()`, `switchToRpc()`). It also carries
`getHandler()` / `getClass()`, which is how a guard reads decorators you put on the route, like
`@Roles("admin")`.

## The other three, briefly

- An **interceptor** sees both sides of the handler, so it's where timing, logging, caching and
  "wrap every response in `{ data }`" live.
- A **pipe** runs on a single argument on its way in — `"42"` → `42`, or reject the body as a
  400 when it doesn't match the DTO.
- An **exception filter** is the last stop *for a failed request*: whatever was thrown anywhere
  in that chain becomes a status code and a response body here (JSON by default — a filter can
  render or redirect instead).

You don't need to be able to write these yet. You need to be able to *read* a codebase and say
"that's a guard, so it's about permission" — the units after this one build each one properly.

<!--more-->

**Wildcards in `forRoutes`.** A bare `"*"` is what the Nest 12 docs write for "every route".
Under the hood, the Express adapter has run on Express 5 since Nest 11, and Express 5 only
accepts *named* wildcards such as `{*splat}` — Nest converts a bare `"*"` for you, silently. A
wildcard after a prefix is different: `"users/*"` still works but logs an "Unsupported route
path" warning at boot, so write `"users/{*splat}"`.
