## Nested objects need two decorators

`class-validator` doesn't recurse by default, and `class-transformer` can't know which class a
nested plain object should become:

```ts
export class AddressDto {
  @IsString() street: string;
  @Matches(/^\d{5}$/) zip: string;
}

export class CreateCustomerDto {
  @IsString() name: string;

  @ValidateNested()          // recurse into it
  @Type(() => AddressDto)    // …as an AddressDto
  address: AddressDto;

  @ValidateNested({ each: true })
  @Type(() => AddressDto)
  @ArrayMaxSize(5)
  otherAddresses: AddressDto[];
}
```

`@Type` doesn't need `transform: true`: `ValidationPipe` always converts the body to class
instances before validating, and `transform` only decides whether the handler receives them.

Forget `@ValidateNested` and the whole subtree is skipped. Forget `@Type` and the nested value
stays a plain object, so its decorators are never found — silently unvalidated. With
`whitelist: true` it's worse: the plain object's keys count as undecorated and get stripped, so
the handler receives `address: {}`. This pair is the single most common validation hole in a
Nest codebase.

## PATCH: derive, don't duplicate

```ts
export class UpdateOrderDto extends PartialType(CreateOrderDto) {}
```

`PartialType` (from `@nestjs/mapped-types`, or `@nestjs/swagger` if you use Swagger) copies every
property and its decorators, adding `@IsOptional()`. `PickType`, `OmitType` and
`IntersectionType` cover the rest. Hand-copying a DTO for the update route means the day
someone adds `@MaxLength` to create, PATCH quietly accepts a 10 000-character note.

Know exactly what `@IsOptional()` lets through: it skips every validator on the property when
the value is `undefined` **or `null`**. So the derived DTO accepts `{ "customerId": null }`,
and a handler that writes the DTO straight to the row nulls a required column — a database
error at best. To mean "may be absent, never null":

```ts
export class UpdateOrderDto extends PartialType(CreateOrderDto, { skipNullProperties: false }) {}

// on a hand-written DTO, the same rule:
@ValidateIf((_, value) => value !== undefined)
@IsString()
note?: string;
```

`skipNullProperties: false` makes `PartialType` add that `@ValidateIf` instead of
`@IsOptional()`, so `null` meets the original validators and fails them. And with
`whitelist: true`, "absent" and "present but stripped" look identical to your handler, which
matters when your update is a partial write.

<!--more-->

Two settings change the missing-`@Type` failure mode. `forbidUnknownValues: true` turns it
into a 400 ("an unknown value was passed to the validate function") instead of a silent pass —
Nest's `ValidationPipe` defaults that option to `false`, even though `class-validator` itself
has defaulted to `true` since 0.14. And `enableImplicitConversion` can infer a single nested
class from the property's TypeScript type, but never an array's element type: `AddressDto[]` is
just `Array` at runtime. Write `@Type` every time rather than remembering which case you're in.
