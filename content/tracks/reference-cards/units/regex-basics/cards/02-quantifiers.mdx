---
id: quantifiers
title: Quantifiers — greedy by default, lazy with ?
---

`*` (0 or more), `+` (1 or more), `?` (0 or 1), `{3}` (exactly 3), `{2,}` (2 or more) and `{2,4}`
(2 to 4) apply to the item just before them: a character, a class or a group.

Quantifiers are **greedy** — they take as much as they can and give back only what the rest of the
pattern needs. A `?` after one makes it **lazy**: as little as possible.

```js
const html = "<b>bold</b> and <i>it</i>";
html.match(/<.+>/)[0];    // "<b>bold</b> and <i>it</i>" — first < to the last >
html.match(/<.+?>/)[0];   // "<b>"
html.match(/<[^>]+>/)[0]; // "<b>" — a negated class can't run past ">" at all
```

The negated class often states the intent better than laziness does. (For real HTML, use a parser,
not a regex.)
