title: A debounce is a timer you keep resetting
---

A debounced function waits for the calls to **stop**. Each call cancels the timer the previous
call started and starts a new one, so `fn` runs once, `wait` ms after the **last** call, with
that call's arguments.

`debounce` is a function that takes your function and returns a new one. The timer handle
lives in the closure, shared by every call to the returned function:

```js
function debounce(fn, wait) {
  let timer; // shared by every call to the function we return

  return (...args) => {
    clearTimeout(timer);                        // cancel the previous call's timer
    timer = setTimeout(() => fn(...args), wait); // and start the clock again
  };
}

const search = debounce((q) => console.log("search", q), 300);
search("r");
search("re");
search("rea"); // ...then 300 ms of silence
// search rea
```

Three calls, one run, with the **last** arguments. `"r"` and `"re"` were scheduled, then
cancelled before their 300 ms were up.

That's the **trailing edge**: the run happens at the end of the burst. It's what you want when
only the final value matters (search-as-you-type, autosave, "resize finished"). Its weakness is
the flip side of its strength: if the calls never stop, `fn` never runs.

Two things this ten-line version gets wrong, which the medium tier fixes:

- **`this` is lost.** An arrow function has no `this` of its own, and `fn(...args)` calls `fn`
  as a plain function. Attach the debounced function to an object as a method and `fn` won't
  see that object.
- **There's no way to cancel or flush.** A component being torn down needs to drop the pending
  call (or run it now), and nothing outside the closure can reach `timer`.
