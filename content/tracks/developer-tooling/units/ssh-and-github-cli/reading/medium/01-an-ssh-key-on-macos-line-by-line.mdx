title: An SSH key on macOS, line by line
---

GitHub's macOS instructions, with what each step actually does. Run them in your own terminal
(the transcripts are OpenSSH 10.2 on macOS 26; older versions word the prompts a little
differently).

## 1. Make the key pair

```sh
% ssh-keygen -t ed25519 -C "ada@example.com"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/Users/ada/.ssh/id_ed25519):
Enter passphrase for "/Users/ada/.ssh/id_ed25519" (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /Users/ada/.ssh/id_ed25519
Your public key has been saved in /Users/ada/.ssh/id_ed25519.pub
The key fingerprint is:
SHA256:… ada@example.com
```

- **`-t ed25519`** — the key type GitHub's instructions use (an Ed25519 public key is one short line).
- **`-C`** — a comment stored at the end of the public key. Without it, OpenSSH uses
  `user@hostname`, which puts your machine's name into every server you register the key with.
- **The passphrase** encrypts the private key on disk. A stolen laptop backup or a leaked
  dotfiles repo then holds a file that's useless without it. Use one.

`ssh-keygen` writes the private key readable only by you (`-rw-------`). Copy keys around by hand
and loosen that, and OpenSSH refuses them: `WARNING: UNPROTECTED PRIVATE KEY FILE!` …
`Permissions 0644 for '…' are too open.` `chmod 600` the private key to fix it.

## 2. Let the agent remember the passphrase

Typing the passphrase on every `git push` would get old. The **ssh-agent** holds unlocked keys
in memory, and on macOS the Keychain can store the passphrase so the agent unlocks the key for
you:

```sh
# ~/.ssh/config
Host github.com
  AddKeysToAgent yes
  UseKeychain yes
  IdentityFile ~/.ssh/id_ed25519
```

```sh
ssh-add --apple-use-keychain ~/.ssh/id_ed25519    # asks for the passphrase once, saves it
```

macOS already runs an agent for your login session (`echo $SSH_AUTH_SOCK` shows its socket);
GitHub's guide also starts one explicitly with `eval "$(ssh-agent -s)"`. `UseKeychain` and
`--apple-use-keychain` are Apple additions — a non-Apple OpenSSH (Homebrew's, say) stops at
`Bad configuration option: usekeychain`, which is what GitHub's `IgnoreUnknown UseKeychain`
workaround is for. (Before macOS 12, the flag was `-K`.)

## 3. Give GitHub the public half, and test

Paste the contents of `~/.ssh/id_ed25519.pub` into GitHub → Settings → SSH and GPG keys (or
`gh ssh-key add ~/.ssh/id_ed25519.pub`). Then:

```sh
% ssh -T git@github.com
Hi ada! You've successfully authenticated, but GitHub does not provide shell access.
% echo $?
1
```

That **is** success. `-T` asks for no terminal, GitHub refuses to give you a shell, and the
command exits `1` — GitHub's docs say to expect exactly that. The line that matters is the
username: it's the account your key belongs to.

Failure looks different:

```sh
git@github.com: Permission denied (publickey).        # exit 255 — ssh itself failed
```

That means GitHub accepted none of the keys offered — usually the public key was never added,
or `ssh` offered a different key file than the one you registered.

Finally, point existing clones at SSH: `git remote set-url origin git@github.com:acme/api.git`.
