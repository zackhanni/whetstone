title: A02 Security Misconfiguration
---

Insecure defaults left in place: verbose errors and stack traces, default accounts, sample apps,
storage buckets shared with the internet, missing security headers.

```ts
// server.ts — started without NODE_ENV=production
app.get("/orders/:id", async (req, res, next) => {
  try {
    res.json(await getOrder(req.params.id));
  } catch (err) {
    next(err); // Express's default error handler sends err.stack unless NODE_ENV is "production"
  }
});
```

The code is fine; the deployment isn't. Express's docs: the stack trace "is not included in the
production environment", and production mode means `NODE_ENV=production`. Forget it, and every
failing request tells the attacker your file paths and library versions.

OWASP's fixes: an automated, repeatable hardening process that configures every environment the
same way, a minimal platform with nothing unused installed, regular review of cloud storage
permissions, and security headers on every response (the `security-headers` unit).
