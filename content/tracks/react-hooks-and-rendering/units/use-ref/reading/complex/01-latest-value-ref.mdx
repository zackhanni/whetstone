title: The "latest value" ref to escape a stale closure
---

A callback created in one render closes over that render's variables. If it runs much
later — inside a long-lived interval, a subscription, an event listener you attach
once — it sees the *old* values. The classic fix is a ref that you keep pointing at
the current value.

```jsx
function ChatRoom({ onMessage }) {
  // Keep a ref that always holds the newest onMessage.
  const onMessageRef = useRef(onMessage);
  useEffect(() => {
    onMessageRef.current = onMessage; // refresh every render — cheap, no re-render
  });

  useEffect(() => {
    const socket = connect();
    // This listener is attached ONCE, but reads the latest handler each time.
    socket.on("message", (m) => onMessageRef.current(m));
    return () => socket.close();
  }, []); // stays mounted; not torn down when onMessage changes
}
```

Without the ref you'd have two bad choices: add `onMessage` to the effect's deps and
reconnect the socket on every render, or omit it and call a stale `onMessage`
forever. The ref decouples *when the callback runs* from *which version it runs* — a
mutable box that the effect reads at call time instead of capturing at setup time.

<!--more-->

This is exactly why a ref, not state, fits here: refreshing `onMessageRef.current`
must **not** re-run the connection effect. A state update would; a ref write is
silent, which is the whole point.
