---
id: stale-closures
title: Stale state in async callbacks
---

A callback captures the state value from the render that created it. If it runs
later — a timeout, an interval, a resolved promise — it may use a stale value.

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // ❌ count is frozen at 0 for this closure
    }, 1000);
    return () => clearInterval(id);
  }, []);
  return <h1>{count}</h1>;
}
```

The interval's closure captured `count = 0`, so it sets 1 forever. The functional
updater sidesteps the closure entirely — it always reads React's current value:

```jsx
setCount((c) => c + 1); // ✅ climbs 1, 2, 3, …
```

<!--more-->

This is the same trap the `useEffect` unit's counter falls into — which is why
`setX((prev) => ...)` is the default whenever a setter runs inside an async callback.
