---
id: stale-closures
title: Stale state in async callbacks
---

A function created during a render sees that render's state, for as long as it lives. If it
runs later — after an `await`, in a timeout, from a subscription — the value it reads may be
several updates old.

```jsx
function SaveButton() {
  const [saves, setSaves] = useState(0);

  async function handleSave() {
    await api.save();
    setSaves(saves + 1); // ❌ `saves` is from the render that handled the click
  }

  return <button onClick={handleSave}>Saved {saves} times</button>;
}
```

Click twice before the first save returns. Nothing has re-rendered between the clicks, so both
run the same handler from the same render, both read `saves = 0`, and both set 1. Two saves,
and the counter says 1.

The updater form doesn't read the closure at all. React calls it with the latest queued value:

```jsx
setSaves((s) => s + 1); // ✅ 0 → 1 → 2
```

<!--more-->

This is why `setX((prev) => ...)` is the default whenever a setter runs after an `await` or
inside a timer, interval or subscription callback. The `useEffect` unit shows the same trap
inside an interval.
