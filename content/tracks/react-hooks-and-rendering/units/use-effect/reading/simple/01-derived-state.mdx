---
id: derived-state
title: Don't derive state in an effect
---

> **Rule of thumb:** if you can compute it during render, don't put it in an Effect.

```jsx
// ❌ Don't: derive state with an Effect
const [fullName, setFullName] = useState("");
useEffect(() => {
  setFullName(first + " " + last);
}, [first, last]);

// ✅ Do: just compute it during render
const fullName = first + " " + last;
```

The Effect version renders once with a stale value and then re-renders. The plain version
is correct on the very first render and does no extra work.

<!--more-->

### The deeper reason

Effects run *after* render and commit. Deriving state in an Effect means React paints once
with the old value, then re-renders with the corrected one — a wasted render every time the
inputs change, and a flash of stale UI in the worst case. Computing during render sidesteps
the whole round-trip. If the computation is genuinely expensive, reach for `useMemo` — still
during render, never an Effect.
