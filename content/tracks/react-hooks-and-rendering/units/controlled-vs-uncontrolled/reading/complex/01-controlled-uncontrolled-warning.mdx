---
id: controlled-uncontrolled-warning
title: Data that arrives late — the warning, and the field that stays empty
---

An input is controlled when it gets a `value`, and `value={undefined}` (or `null`) counts as
no value at all. An input mustn't switch between the two during its life. If `value` starts
`undefined` and later becomes a string, React logs:

> A component is changing an uncontrolled input to be controlled.

The classic cause is binding `value` straight to data that hasn't loaded yet:

```jsx
function NameField({ user, onNameChange }) {
  // 🐛 user is {} until the fetch resolves: value={undefined}, then value="Ada"
  return <input value={user.name} onChange={(e) => onNameChange(e.target.value)} />;
}
```

The fix is to keep `value` a string from the first render (react.dev's own advice):

```jsx
<input value={user.name ?? ""} onChange={(e) => onNameChange(e.target.value)} />
```

The mirror-image warning — _"changing a controlled input to be uncontrolled"_ — happens when
`value` goes from a string back to `undefined`/`null` (resetting state to `undefined`, say).
Same rule fixes both: pick controlled **or** uncontrolled and keep `value` consistently
defined (or consistently absent) for the input's whole life.

### The trap: copying late data into state

Now the version most forms actually have — local state seeded from the prop, so the user
can edit it:

```jsx
function NameForm({ user }) {
  const [name, setName] = useState(user.name); // 🐛 reads user.name once, while it's undefined
  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}
```

This one does *not* warn when the data loads. `useState` ignores its argument after the
first render, so `name` stays `undefined`: the field stays empty and nothing switched. The
warning fires later, on the first keystroke, when `setName("x")` makes `value` a string.

`useState(user.name ?? "")` silences that warning — and leaves the bug: the field is now a
controlled empty string, and "Ada" still never appears. The fix is to create the state
*after* the data exists:

```jsx
// Render the form only once there's something to edit…
{user ? <NameForm initialName={user.name} /> : <p>Loading…</p>}

// …or remount it when the data arrives: a new key means fresh state from useState.
<NameForm key={user?.id ?? "loading"} initialName={user?.name ?? ""} />
```

Avoid the third option people reach for, an effect that copies the prop into state: it
renders once with the stale value first, and without the right dependencies it overwrites
whatever the user types (the [Untangling a component with too many effects](/learn/react-hooks-and-rendering/untangling-effects) unit takes that bug apart).
